# ポートフォリオ再設計 設計書

日付: 2026-11-20 / 対象: `sakai1250.github.io`(静的サイト) / 状態: 承認待ち

## 1. 意図(なぜやるか)

現状のサイトは「AIが作った」ように見える。原因は、クリーム背景+ネイビー+ゴールド、細い明朝系の見出し(Cormorant Garamond)、白い角丸カード+柔らかい影、ピル型チップ、見出し左のゴールドの縦棒という、AIが「高級な編集デザイン」として最初に出しがちな部品の組み合わせにある。

目指す姿は「シンプルで、技術のすごさが伝わり、今風」。読者は研究者・採用担当・エンジニア(README の想定)で、主役は研究業績(論文 18 件: 国際 7 + 国内 11)。技術のすごさは装飾ではなく、(a) 情報整理の精度、(b) 実際に動く研究の図、で見せる。

## 2. ゴール / 非ゴール / アンチゴール

**ゴール**
- 方向は「A: Index(紙面)を土台に、C: Live の動く図をヒーローに」(モック承認済み)。近白+黒+アクセント1色、Geist / Geist Mono、細い罫線ベース。カード・影・ピル・ゴールドを廃止する。
- ヒーローに、シンプルなニューラルネットワークの図(Canvas 2D、依存ライブラリなし)を置く。
- 研究業績の論文一覧(18 件)を `題名 / 著者 / 会場 / 受賞タグ` に構造化し、A の表組みを実現する。
- 今風の標準機能を使う: OKLCH、`@layer`、コンテナクエリ、`text-wrap`、スクロール連動アニメーション、View Transitions。
- ライト/ダーク、日本語/英語、モバイルを維持する。
- `scripts/run_local_validation.py` が全通過する。

**非ゴール**
- フレームワーク・ビルド工程の導入(README の「ビルド不要」を維持)。
- `⌘K` コマンドパレット(B の要素)。後から足せる余地は残す。
- WebGL / WebGPU(今回の図には見た目の利益がなく、対応も限られる)。
- 内容の変更。論文・受賞・文言は1文字も変えない。
- 新しい外部サービス・新しい外部リクエスト(フォントは既存と同じ Google Fonts)。

**アンチゴール(動いても失敗とみなす)**
- 「ダーク+発光グラデ+等幅フォント」の開発ツール風AIサイトに見えること。
- JS が無効・遅延・失敗のときに内容が読めなくなること(README の必須要件)。
- 動く図が読みやすさ・CPU・モバイルの電池を犠牲にすること。
- コントラスト・フォーカス・キーボード操作が現状より悪化すること。

## 3. 制約(調査で判明したこと)

- 静的 HTML/CSS/JS、GitHub Pages。主要コンテンツは JS なしで見えること。
- `scripts/` に `maintain_*.py` が 31 本、`check_*.py` が多数ある。`run_local_validation.py` は保守スクリプトを適用し、**適用後に差分が出ないこと**を要求する。
- `style.css` は次の 5 本の保守スクリプトが特定ブロックを読み書きする: `maintain_header_stat_links`、`maintain_heading_hierarchy`、`maintain_static_portfolio_polish`、`maintain_storage_resilience`、`maintain_tabs`。全面書き換えでは、これらが期待するブロックを引き継ぐか、スクリプト側を新デザインに合わせて更新する。検査を緩めて通すことはしない。
- `maintain_research_awards.py` と `maintain_static_fallbacks.py` は `<li data-year="…"><span class="badge-year">…</span>` の構造を正規表現で前提にしている。**受賞(Awards)など他のリストのマークアップは変えない。**
- `main.js` は `.repo-list li[data-year]`、`.chip[data-year]`、`.repo-list > li`(件数集計)に依存する。これらのクラス・属性は維持する。
- 日英切替は `<span lang="ja">` / `<span lang="en">` の併記と `html[data-lang]`。新しい可視テキストは日英両方を用意し、既存のローカライズ系チェックを通す。
- 論文は `<li data-year>` 内の自由文(著者, “題名,” `<div class="muted">会場</div>` + Paper リンク)。国内発表は「」形式が混在する。
- `index.html?v=` のアセットハッシュは `maintain_asset_versions` が自動更新する。
- アクセント色(朱色 約 `#EE4B24`)は白背景で約 3.6:1 しかなく、小さい文字の色には使えない。**鮮やかな朱(`--accent-mark`)は文字色に使わず、点・罫線・大きな要素にだけ使う。文字・リンク用の `--accent` は、ライトでは同じ色相で明度を下げる(oklch(0.56 0.19 34)、4.97:1)。既存の inline style 27 箇所と `main.js` が `--accent` を文字・線の色に使っているため、変数名は維持して値だけ変える。**

## 4. アプローチ(検討と選択)

| 案 | 内容 | 得失 |
|---|---|---|
| 1 | CSS だけ作り替え。HTML はほぼそのまま | 保守スクリプトへの影響が小さい。論文の題名だけを大きくできず、A の見せ場が作れない |
| **2(選択)** | 論文一覧を構造化し、3 段階で作り替え | A の見た目をモック通りに出せる。変換が保守スクリプトとぶつかる恐れがあるため、着手前に基準を取り、段階ごとに検証する |
| 3 | Astro 等へ移行 | README・保守スクリプト・チェックが静的 HTML 前提。来訪者から見える利益が小さい。却下 |

選択理由: 主役の論文一覧を A の表組みで見せるには構造化が要る。段階に分ければ、途中で止めても崩れない。

## 5. 決定済みの設計

### 5.1 デザインシステム
- **色**: OKLCH のトークンを定義する。ライトは近白の背景、近黒の文字。ダークは近黒の背景。アクセントは朱色の 1 色相(鮮やかな `--accent-mark`、文字・リンク用に明度を下げた `--accent`)。罫線は 1px のヘアライン。アクセントは受賞の点・ヒーロー内の強調・大きな要素に使う。
- **書体**: 本文・見出しは Geist、年・会場・ラベルなどのメタデータは Geist Mono、日本語は Noto Sans JP。Cormorant Garamond は廃止。読み込み方法は既存(Google Fonts、`media=print` + `onload`)を踏襲する。
- **形**: 影なし、角丸は最小限、カードは罫線に置き換える。ピル型チップは、選択中を下線+太字で示すテキストのフィルタにする。ゴールドの縦棒とタイムラインの輪は廃止する。
- **今風の標準機能**: `@layer`(reset / tokens / base / layout / components)、コンテナクエリ(論文行の列落とし)、`text-wrap: balance`(見出し)・`pretty`(本文)、`color-mix()`(派生色)。

### 5.2 レイアウト(モック A 準拠)
- 上段に細いナビ(略称・Research / Engineering・CV・JA/EN・テーマ)。その下に巨大な名前、役割 1 行、研究領域 4 行(番号つき等幅)。
- 本文は左の固定レール(セクション名・件数)+右の一覧の 2 カラム。連絡先リンク(旧サイドバーのカード)は、レール側の控えめなリンク列にする。名前の二重表示を解消する。
- モバイルは 1 カラム。ヘッダーの 18 / 22 / 14 のカウントアップは廃止し、静的な等幅表示にする(リンク先は `maintain_header_stat_links` の規則どおり維持)。

### 5.3 ヒーローの動く図(第 2 段階)
- ヒーローは、ライトでは紙色の背景に黒インクの線、ダークでは暗い背景に明るい線で描く(テーマに従う。ユーザー指示 2026-11-20: ライト版は図の背景もライトにする。旧案の「どちらでも暗い帯」は撤回)。
- 図は「普通のニューラルネットワーク」: 全結合の順伝播型(層 4-6-6-3)を、細い罫線の辺と小さな円のノードで描く。入力から出力へ、およそ 4 秒に 1 回、ゆっくり活性化の波が流れる。派手な演出・説明文・カウンターは置かない(ユーザー指示、2026-11-20。旧案の複数カメラ追跡と「説明用シミュレーション」表記は撤回)。
- 色はモックの黄緑ではなく、サイト全体のアクセント(朱色)に統一する。
- 制御: `prefers-reduced-motion` では静止フレーム。画面外(IntersectionObserver)とタブ非表示では停止。DPR は最大 2。リサイズ対応。JS が無い・失敗したときは canvas を出さず単色の帯にし、内容には影響させない。
- 読み込みを妨げない(load 後に開始)。新しい外部リクエストなし。装飾なので `aria-hidden`。

### 5.4 論文一覧の構造化(第 3 段階)
- 対象は `#research-research-achievements` の `.repo-list > li`(18 件: 国際会議 7 件 + 国内学会 11 件)のみ。「55 件」は研究タブ全体のフィルタ件数で、対象ではない。
- `li[data-year]` と `.badge-year` は維持し、内側に題名・著者・会場・受賞タグを表す要素を足す。
- 変換は、冪等な `scripts/maintain_publication_structure.py` と、対応する `check_*.py` で行う(既存の保守スクリプトと同じ流儀)。**変換の前後で、空白を正規化した可視テキストが完全一致すること**を機械的に検証する。Paper リンクと `aria-label` も保持する。
- 受賞タグは、会場文の中にある既存の語(例: `Oral`、`Outstanding Paper Award`)を要素で包むだけにする。文言は増減させない。

### 5.5 今風の機能の入れ方(進化的に)
- **スクロール連動**: 読書進捗バー(現在は `initReadingProgress`)を `animation-timeline: scroll()` に置き換える。非対応ブラウザは現行の JS 動作か非表示にする。スクロール出現(reveal)は採用しない。リポジトリの方針(重要なセクションを opacity 0 で始めない。`maintain_storage_resilience.py` が強制)に反し、AI テンプレの定番演出でもあるため。
- **View Transitions**: 研究/開発タブ、言語、テーマの切替に `document.startViewTransition` を使う。非対応なら即時に切り替える。
- 想定ブラウザは直近 2 年の evergreen。非対応でも内容は必ず読める(機能が落ちるだけ)。

### 5.6 段階と検証
- **第 0 段階(基準)**: 変更前に `run_local_validation.py` を実行し、結果を記録する。主要ビューの基準スクリーンショットを撮る(PC/モバイル × ライト/ダーク × 日本語/英語 × 研究/開発)。
- **第 1 段階**: 色・書体・レイアウトの置き換え(`style.css` 全面+ヘッダー/サイドバーの最小限の HTML 変更)。
- **第 2 段階**: ヒーローと動く図。
- **第 3 段階**: 論文一覧の構造化。
- 各段階の終わりで確認する: `run_local_validation.py` 全通過、主要ビューの目視、JS 無効での可読性、キーボード・フォーカス、文字コントラスト(AA 4.5:1)。各段階は単独で止められ、元に戻せる単位にする(段階ごとのコミットを推奨。コミットは依頼があったときだけ行う)。

## 6. ビルダーに任せること
- 具体的な色値・余白スケール・文字サイズ・ブレークポイント。
- アバター画像の扱い(ヒーロー内に小さく置くか、レールに置くか)。
- 変換スクリプトの正規表現の実装、「」形式の国内発表の扱い。
- 保守スクリプトが期待する CSS ブロックの個別対応(引き継ぐか、スクリプトを更新するか)。
- Engineering タブ(アプリ・プレイグラウンド・Qiita・技術スタック)、連絡フォーム、モーダルの再スタイル。
- 新しいスクリプトを `run_local_validation.py` と README の検証説明に登録すること(`check_validation_docs.py` の要求に合わせる)。

## 7. 設計者(私)の判断 — 確認してください
1. アクセントは朱色 1 色に統一し、モックの黄緑は使わない。
2. ヒーローの背景と図は、テーマに従う(ライト=紙色に黒インク、ダーク=暗背景)。当初の「ライトでも暗い帯」はユーザー指示で撤回。
3. ヘッダーの統計(18 / 22 / 14)のカウントアップは廃止し、静的表示にする。
4. フォントは既存と同じ Google Fonts 経由(自前ホストしない)。
5. この設計書は `docs/superpowers/specs/` に置いた。GitHub Pages では公開 URL からも見える。非公開にしたい場合は置き場所を変える。コミットはしていない。
